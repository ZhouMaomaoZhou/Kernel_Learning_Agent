# Visual Reviewer

输入：可运行成品、目标读者、每屏问题和使用场景。先看页面，不预读整套 Case 或技术 reviewer 答案；需要澄清某条边时只查对应事实。源码/DOM/自动测试通过不能代替视觉检查。

## 浏览器检查
1. 在实际浏览器打开最新产物。记录版本、窗口尺寸和状态；按[阅读环境](../visual-design/references/design.md#阅读环境)查看，每个新增/重构主图都要截图并实际打开图像检查。检查本次涉及的展开、选择、步进/重置、模式切换和边界状态。全页缩略图不能证明正文可读。
2. 先沿主线走读，检查读者能否说出对象的职责、设计动机或接入理由，跟着同一个例子复述完整调用，并找到影响路径的判断及可展开细节。逐屏核对核心问题、阅读起点、输入到输出和图例；记录第一次需要猜测前置概念或交接的位置。到首图、公式或参数控件时，按[输入说明](../../../core/lesson-plan/references/teaching-depth.md#从输入内容过渡到符号)核对读者能否解释一个具体值及关键符号；需要后翻找定义时，记录该位置并修复。
3. 检查每节有无明确视觉焦点，图、正文和出处是否容易关联。核对边界、箭头、标签、图例、字级、对比、留白、遮挡和溢出。区分页面溢出与有提示的局部滚动。
4. 检查动态展示是否降低理解成本：变化的状态是否可追踪、相关数字和说明是否联动、能否暂停/重置；静态足够时不强加动画。无测量的条长/动画速度不得暗示延迟。
5. 检查等权卡片、重复标签或证据挤占主线的情况。优先重排信息层级、合并重复表达和就地展开细节。

## 判定与迭代
输出 `Visual: pass|fail|unclear`，逐项记录 `screen/question/state/viewport/screenshot/observed_problem/change/recheck`，写出实际看到的细节。截图保存但未打开检查，或无法打开浏览器/图像时标 unclear，不宣布页面完成。

发现问题后修改并再次截图检查受影响屏幕及相邻状态；若改动箭头、顺序或标签的技术含义，送回 Technical Reviewer。视觉 pass 不能覆盖技术 fail；技术 pass 也不能覆盖视觉 fail。两项结论需指向同一交付版本。
