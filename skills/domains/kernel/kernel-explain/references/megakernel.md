# Megakernel：任务、角色与 buffer

用于讲解一个 launch 内存在专职 worker、异步搬运、矩阵引擎和消费者的实现。按当前源码建模；不把某个案例的工作组数、tile 或调度策略推广成通则。

## 先拆四个观察层次

1. **任务分配**：launch grid、resident CTA、循环领取的 task、task 内 block/atom 分开命名。用一个非零 task 追到 CTA；说明无 producer task 的 CTA 是否仍参与消费或退出。grid 大小不能替代 occupancy 证据。
2. **角色生命周期**：不只列出“谁是 producer / consumer”，还检查模式分支、提前进入、等待、角色退休后的接力，以及同步范围。源码中有 Mix / Norm 命名不代表它们永远由两个固定 WG 串行执行；共享队列不能强行指定实际抢到任务的 WG。
3. **数据驻留**：从一个有效元素追到 local、shared、TMEM 和 global 的生产者与消费者。舍入、重读、分支、统计量与跨调用状态都明确标注。A、原始输入、数学结果、物化输出不能混称“数据”。
4. **buffer 周转**：注明一个 slot 保存的逻辑单位与寿命，例如 atom、K block、整个 split task。四个 A stage 不一定代表四个 K block。逐条记录 producer → ready → wait → consume → release，至少展示两个连续工作单元与一次槽位复用。

给每个图一个问题；用共同的选中 task/元素连接放大视图。架构图回答分工，数据流图回答值的去向，状态图回答能否覆盖槽。不要反复绘制同一排阶段框。

## 把 overlap 讲成可核查条件

- 分清不同输入分支的异步到达、Post 与矩阵引擎的供料、跨 block 的搬算、跨 task 的预取、退休 worker 的消费接力；跨 CUDA stream 又是另一层。
- 默认 workload 若只有一个 block/task，明确哪些跨块或下一任务机会在该例中不存在；切换参数要更新图、数量和文字。
- 画源码支持的一种合法离散状态序列，标明省略步骤。无 trace 时不称其为真实调度，不用条宽、速度或百分比暗示延迟。
- slot 释放与结果可见是不同事件。跨 CTA 消费还需要写入完成、release/acquire 与正确同步域；CTA barrier 不能代替全局协议。多个输出消费域可能有不同的就绪条件。

## 讲清收益对应的账

比较前先对齐模型、数值边界与输出范围。分别列出少了哪些 launch、哪些重复工作、什么驻留/复用机会，以及仍有的 global 物化、重读、scratch、join 和资源压力。

有效计算与固定 tile 工作并列；填充行即使最终输出被 mask，也可能参与前面的矩形运算。预留容量、源码写入、TMA copy extent 与实测 DRAM 流量各用自己的单位与范围。一个优化消除了重算，不保证在极小 shape 下总工作或延迟下降。

## 两种审查分别做

技术审查手算一个非零 lane/最后 block，追一条完整发布/等待/释放链和跨 CTA 可见性，并检查模式切换的消费者身份。视觉审查从主图冷读这些问题，实际切换任务/模式/参数、步进和重置，截图检查填充标记、箭头、状态同步与局部滚动。两个结论对应同一成品版本。
